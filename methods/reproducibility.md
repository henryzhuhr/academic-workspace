# Reproducibility

本规范定义计算型研究的最低复现合同。目标不是强制统一语言或框架，而是让未来的自己或合作者知道如何从输入得到关键结果。

## 最低要求

项目 `analysis/README.md` 至少说明：

1. 研究环境：操作系统要求、语言、关键软件和依赖锁定方式。
2. 输入：使用哪些数据版本、路径或数据集标识。
3. 入口：从哪个命令、脚本、notebook 或工作流开始。
4. 输出：结果写到哪里，哪些文件是关键结果。
5. 参数：随机种子、模型设置、人工选择和不可自动化步骤。
6. 验证：成功运行的判据，以及与论文或报告中结论的对应关系。

## 运行记录

对影响研究结论的运行，在 `analysis/runs/` 中保留一份轻量 Markdown 或 JSON 记录，至少包含日期、代码版本、输入版本、参数、环境和输出路径。大型日志与中间文件默认外置或忽略。

## Notebook

Notebook 适合探索，不应成为唯一无法批量执行的分析记录。用于正式结果时，应清理执行顺序、固定随机性，并在 `analysis/README.md` 给出从干净环境运行的方法。

## 非计算型项目

若项目不包含计算分析，在 `analysis/README.md` 明确标注“不适用”，并说明证据整理、编码或论证过程如何追溯。
