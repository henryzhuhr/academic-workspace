# Data Management

本规范适用于所有项目的数据、访谈、档案、实验材料和其他可作为证据的原始材料。

## 分类

| Classification | 含义 | 默认存储策略 |
| --- | --- | --- |
| `public` | 可合法公开和再分发 | 小型数据可进入 Git；大型数据外置 |
| `internal` | 仅供本人或团队使用 | 仓库外存储，Git 保存元数据和处理代码 |
| `sensitive` | 包含个人、机构或潜在伤害信息 | 加密或受控位置，最小权限访问 |
| `restricted` | 受合同、伦理审批或许可严格限制 | 仅存于明确批准的位置，不在普通同步盘复制 |

项目级分类记录在 `project.json.dataClassification`。若同一项目包含不同等级的数据，以最高等级作为项目默认值，并在数据登记表中逐项标明例外。

## 数据登记表

每个项目的 `data/README.md` 至少记录：

- 稳定数据集标识和简短说明；
- 来源、获取日期、负责人和获取方式；
- 许可、伦理或使用限制；
- 分类等级和仓库外存储位置；
- 文件格式、规模、校验值或版本；
- 从原始数据到处理数据的脚本或步骤；
- 可访问者和保留期限（如适用）。

不得把访问令牌、密码、私钥或个人身份信息写入登记表。

登记位置优先使用逻辑数据集标识、仓库相对入口或可移植 URI。设备专属绝对路径放入项目中被 Git 忽略的 `data/locations.local.json`；登记表必须说明其他设备如何重建该映射。

## 不可变性与派生关系

- `data/raw/` 中的原始材料只读，不覆盖、不原地清洗。
- 清洗和转换结果进入 `data/processed/`，并能回溯到输入、代码版本和参数。
- 文件重命名、格式转换和手工修正也属于转换，必须留下记录。
- 不可再生材料至少保留两份独立备份，并记录校验值。

## Git 策略

项目模板默认忽略 raw、processed 和 runs 中的载荷。只有小型、公开、许可允许且确有复现价值的数据才适合进入 Git；调整忽略规则时在数据登记表说明理由。
